# قاعدة بيانات رُمّان

MySQL 8 · InnoDB · `utf8mb4_unicode_ci` · 34 جدولًا + عرضان + 3 محفّزات.
الملف الكامل: [`database/schema.sql`](../database/schema.sql).

## الاصطلاحات

- مفتاح أساسي `id BIGINT UNSIGNED AUTO_INCREMENT` في كل جدول.
- الكيانات المعروضة للعميل لها `uuid` أو `slug` — **لا نكشف الـ id التسلسلي** في الروابط.
- حذف منطقي عبر `deleted_at` في الجداول الأساسية (المستخدمون، الفروع، الأقسام، المنتجات، العناوين).
- كل المبالغ `DECIMAL(12,2)` — ممنوع `FLOAT` مع النقود.
- التخزين بتوقيت UTC والعرض بتوقيت القاهرة في طبقة التطبيق.
- كل مفتاح أجنبي له سلوك حذف صريح (`CASCADE` / `SET NULL` / `RESTRICT`).

## المجموعات

### 1. الحسابات
| الجدول | الدور |
|---|---|
| `users` | العملاء والفريق. يحمل رصيد النقاط والمحفظة وفئة الولاء وإجمالي الإنفاق |
| `refresh_tokens` | جلسات التجديد — تُخزَّن كـ SHA-256 مع الجهاز والـ IP |
| `password_resets` | رموز استعادة كلمة المرور بصلاحية ساعة |

### 2. الفروع
| الجدول | الدور |
|---|---|
| `branches` | الفرع: إحداثيات، مواعيد، رسوم توصيل، حدّ الطلب، حدّ التوصيل المجاني |
| `branch_hours` | مواعيد تفصيلية لكل يوم أسبوع |
| `delivery_zones` | مناطق التوصيل ورسومها وزمنها المتوقّع |

### 3. الكتالوج
| الجدول | الدور |
|---|---|
| `categories` | شجرة أقسام بمستويين + `motif` و`accent_color` لهوية القسم البصرية |
| `brands` | العلامات التجارية، مع علم `is_house_label` لعلامة رُمّان الخاصة |
| `products` | المنتج كاملًا: أسعار، مصدر، قيم غذائية (JSON)، وسوم، تقييمات مجمّعة، فهرس FULLTEXT |
| `product_images` | صور اختيارية (الواجهة تولّد لوحة بصرية بديلة) |

### 4. المخزون
| الجدول | الدور |
|---|---|
| `inventory` | **(فرع × منتج)** فريد: كمية، محجوز، حدّ تنبيه، ممر، سعر خاص بالفرع |
| `inventory_movements` | سجلّ تدقيق لكل حركة: توريد، بيع، حجز، فكّ حجز، تسوية، تلف، مرتجع |

> `quantity` = ما على الرف. `reserved` = محجوز لطلبات قيد التنفيذ.
> **المتاح للبيع = quantity − reserved.**

### 5. السلة والطلب
| الجدول | الدور |
|---|---|
| `carts` / `cart_items` | سلة لكل (عميل × فرع)، مع لقطة سعر وقت الإضافة |
| `orders` | رأس الطلب: الحالة، الدفع، كل المبالغ، الموعد، النقاط |
| `order_items` | **لقطة ثابتة** للاسم والسعر والوحدة — لا تتأثر بتغيّر الكتالوج لاحقًا |
| `order_status_history` | الخط الزمني لكل تغيّر حالة مع من غيّرها |
| `payments` | عمليات الدفع (آخر 4 أرقام فقط — لا بيانات بطاقة) |
| `addresses` | دفتر عناوين العميل بعنوان افتراضي واحد |

### 6. العروض
| الجدول | الدور |
|---|---|
| `coupons` | نسبة/مبلغ/شحن مجاني، سقف خصم، حدّ أدنى، حدود استخدام كليّة ولكل عميل، نطاق (الكل/قسم/منتج) |
| `coupon_redemptions` | سجلّ كل استخدام فعلي — عليه يُبنى فحص «استخدمته من قبل» |
| `promotions` | مساحات تحريرية على الصفحة الرئيسية |

### 7. التفاعل
| الجدول | الدور |
|---|---|
| `reviews` | تقييم واحد لكل (عميل × منتج)، مع علم شراء موثّق |
| `review_votes` | تصويت «مفيد» — صوت واحد لكل عميل |
| `wishlists` | المفضّلة |
| `product_views` | سجلّ المشاهدة (لـ «شاهدت مؤخرًا» والتوصيات) |
| `search_logs` | كلمات البحث (لـ «الأكثر بحثًا») |

### 8. الولاء والتواصل
| الجدول | الدور |
|---|---|
| `loyalty_transactions` | كل حركة نقاط مع الرصيد بعدها |
| `wallet_transactions` | كل حركة محفظة مع الرصيد بعدها |
| `notifications` | إشعارات داخل التطبيق |
| `contact_messages` · `newsletter_subscribers` | خدمة العملاء والنشرة |
| `settings` · `audit_logs` | إعدادات المنصّة وسجلّ تدقيق العمليات الحسّاسة |

## العروض (Views)

| العرض | الفائدة |
|---|---|
| `v_product_stock` | المتاح والسعر الفعّال ومؤشّر نقص المخزون لكل (منتج × فرع) |
| `v_branch_sales` | إيراد وعدد طلبات ومتوسّط قيمة يوميًا لكل فرع |

## المحفّزات (Triggers)

ثلاثة محفّزات على `reviews` (بعد الإضافة/التعديل/الحذف) تعيد حساب
`products.rating_avg` و`rating_count` تلقائيًا — فلا يمكن أن يختلف
المتوسّط المعروض عن التقييمات الفعلية مهما كان مصدر التعديل.

## الفهارس المهمّة

| الفهرس | يخدم |
|---|---|
| `products` FULLTEXT على (الاسم عربي/إنجليزي، الوصف) | البحث |
| `idx_product_category (category_id, status)` | صفحة القسم |
| `uq_inventory (branch_id, product_id)` | كل استعلام سعر/توفّر |
| `idx_inventory_low (branch_id, quantity)` | تنبيهات المخزون |
| `idx_order_branch_status` · `idx_order_status_date` | طابور التجهيز والتقارير |
| `uq_review_user_product` | يمنع تقييمين لنفس العميل على نفس المنتج |
| `uq_cart_product (cart_id, product_id)` | يمنع تكرار الصنف في السلة |

## البيانات الأوّلية

**لا بيانات عيّنة.** `npm run db:bootstrap` يكتب شيئين فقط:

1. **الإعدادات العامّة** في جدول `settings` — اسم العلامة، بيانات
   التواصل، قواعد النقاط، نسبة الضريبة، رمز العملة، حالة المتجر.
   يُكتب الناقص ولا يُدهَس ما عدّلته اللوحة (`ON DUPLICATE KEY UPDATE
   key = key`)، فالسكربت آمن للتكرار.

2. **حساب المدير الأول** — من متغيّرات `ADMIN_*` أو من وسائط سطر
   الأوامر. إن وُجد مدير بالفعل يُخبرك ويخرج بلا تعديل.

كل ما عداه — الفروع والأقسام والعلامات والمنتجات والمخزون والكوبونات
والعروض — يُدخَل من لوحة الإدارة أو عبر استيراد CSV، لأنها بيانات
عملك أنت لا بيانات عيّنة.

### جداول تبقى فارغة حتى يعمل المتجر

هذه الجداول لا يكتب فيها إلّا الاستخدام الفعلي، وأي بذر لها يعني
تقارير كاذبة من أول يوم:

`orders` · `order_items` · `order_status_history` · `payments` ·
`payment_webhooks` · `reviews` · `review_votes` · `loyalty_transactions` ·
`wallet_transactions` · `inventory_movements` · `product_views` ·
`search_logs` · `coupon_redemptions` · `audit_logs`

### الحقول المحسوبة

`products.rating_avg` و`rating_count` تُحدَّثان بمحفّزات (triggers) على
جدول `reviews`. و`sold_count` يزيد عند إنشاء الطلب وينقص عند إلغائه.
و`coupons.used_count` يزيد بالاستخدام. و`inventory.reserved` تديره
معاملة الطلب.

**كلّها غائبة عن قوائم الكتابة البيضاء في لوحة الإدارة** — فلا يمكن
تعديلها يدويًا، ولا تكذب التقارير.
